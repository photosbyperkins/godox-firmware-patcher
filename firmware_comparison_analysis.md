# Cross-Model Firmware Comparison

**Last audited:** 2026-10-13. Status marks: ✅ verified in code · 🔶 partial · ⚠️ unverified ([legend](FINDINGS.md#status-legend)).

## Shared Architectural Design

✅ All five target flash models (AD600Pro II, AD200Pro II, AD100Pro II, V100N, and iT30ProN) run plaintext Thumb-2 code behind a factory bootloader. AD600Pro II, AD200Pro II, AD100Pro II, and iT30ProN run on STM32F4-class MCUs (HSI 16 MHz PLL at 168 MHz, 84 MHz APB1 timer clock). V100N runs on a GD32F450/470 MCU (IRC16M PLL at 240 MHz, TIMERSEL bit set). All five utilize a synchronized algorithmic heat-accumulation engine: pre-calibrated points are accumulated per shot from firmware lookup tables, while an independent timer ISR drains accumulated points during pauses once every 20 calls (0.100 s step) and on timer % 50 (or % 60 on iT30ProN).

Across all five models, timer steps execute at **0.100 s (100 ms)** nominal (derived from hardware timer ISRs with dual-stage prescalers, based on internal RC oscillators ±1%; GD32F4 IRC16M at 240 MHz on V100N), gated by active run flags. The 50-step drain interval is **5.000 s** nominal (**6.000 s** / 60 steps on iT30ProN).

## Architectural Distinctions

1. **Active vs. Passive Cooling:**
   - The **AD600Pro II** features a multi-pin GPIO-driven active cooling fan (`PC14` for Level 1, `PC14 + PA4 + PA7` for Level 2) with physical hardware thermistor monitoring. All custom firmware profiles latch this fan to continuous high speed (Level 2) for maximum continuous heat dissipation.
   - The **AD100Pro II** features an internal chassis cooling fan driven by GPIOC Pin 4 (`fn_08014370`). In factory stock firmware, it engages once heat points exceed 1200 (`0x4B0`), thermistor counts drop below 271.06, or modeling lamp brightness is ≥ 60%. In custom profiles (Tier S, R, X), the fan runs continuously while awake (unless low-battery cutoff `0x2000007A` is set) to actively exhaust tube heat.
   - The **AD200Pro II** body has no internal chassis fan, but its `H200 II` fresnel head (`0x20000095 == 6`) has a built-in cooling fan directly controlled by the body firmware (`fn_080237B0`) via bit-banged I2C slave `0x5C` register `0x01` (engaging when head NTC `[0x200001E6]` is in `151..941`, modeling lamp `> 60`, or after 5 full-power shots). With other heads, the AD200Pro II relies on passive cooling.
   - The **V100N** and **iT30ProN** have no fan driver routines in firmware and rely on passive thermal dissipation through the chassis and head. On the ultra-compact ~120g iT30ProN, thermal density is particularly high, making Tier R (stock single-burst limits + 2× recovery drain) the safest recommended upgrade profile.

2. **Per-Shot Table Architectures:**
   - **AD600Pro II:** Utilizes a single 1D table of 28 halfwords (indexed by power level 0–27).
   - **AD200Pro II:** Utilizes dual modular selectors across 4 distinct 25-entry halfword tables (Tables A, B, C, D) depending on attached head code (`0x20000093` / `0x95`: 1=H200, 2=H200R, 3=H200J, 4=R200, 5=AD-L, 6=H200 II, 7=H200J II) and whether HSS is active.
   - **AD100Pro II:** Utilizes two sets of 11-row × 25-column tables (Table Set 1 at `0x08032D22` for standard/manual, Table Set 2 at `0x08032F48` for HSS ✅). Row = `[0x20000001] & 7` is verified in `fn_08013718` (`0x08013BF4`) and `fn_08016024` (`0x080160BA`) as the **5-step Zoom Focal Length (`0..4` = `28, 35, 50, 70, 85` mm)**: Row 0 (`28 mm`) full power is 100 points ($6000/100 = 60$ shots), Row 1 (`35 mm`) is 90 points ($67$ shots), Row 2 (`50 mm`) is 80 points ($75$ shots), Row 3 (`70 mm`) is 70 points ($86$ shots), and Rows 4–7 (`85 mm`) are 60 points ($100$ shots).
   - **V100N:** Utilizes a full 2D matrix (11 rows × 22 columns) indexed by zoom focal length (Row = index + 1 from table `0x08051694`: Row 0 = special `0x200004DE` flag; Rows 1–10 = 20, 24, 28, 35, 50, 70, 80, 105, 135, 200 mm) and output power level (columns 0–21).
   - **iT30ProN:** Utilizes a 2D matrix (11 rows × 22 columns, with power $P = 0..70$ mapped via `fn_080109BC` in 3/3/4 tenths per stop into columns 21..0). Only rows 0 and 1 are used, selected by a debounced GPIOC pin 15 input (`0x200005B9`, which also switches discharge duration tables at `0x0801588E` and status-bar diffuser icons at `0x08045B0C`). Row 0 = 300 pts at the top column (20 shots), row 1 = 200 pts (30 shots). HSS uses table `0x0804FFAC` (150 pts at 1/1 = 40 shots).
3. **Image Integrity Footer:**
   - The **iT30ProN** image ends with an MD5 footer (MD5 of `file[0:0xA8000]`, filename, length, magic `AA 55 66 99 77 88 22 33`). None of the other models have one. Disassembly of `Godox_G3_v1.1.exe` (`0x00404D1B`) proves G3 only checks `file_size <= 1 MB` and performs no MD5 check, so the footer is verified by the iT30ProN on-chip bootloader (or a newer host tool). Patchers recompute it automatically. The app also shows a "Hot Shoe Upgrading" screen (`0x0802F278`), which suggests a separately updated hot-shoe subsystem (purpose of the V1.02 changes unverified ⚠️).
